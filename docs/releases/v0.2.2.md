## 版本说明

本次为维护更新，重点修复生产配置读取和服务器运维稳定性，保留现有 QQ 运维指令。

## 修复与改进

- **修复生产配置读取**：通过 NoneBot 读取 `.env.prod` 和系统环境变量，避免配置文件已填写但插件仍使用默认值。
- **正常停止服务器**：`/stop` 改为调用 MCSManager 正常停止接口，不再直接强制终止进程。请确认面板中的实例停止命令为 `stop`。
- **完善接口异常处理**：连接失败、超时和异常响应会返回中文提示，不回显包含 API Key 的请求地址；控制操作不会自动重试。
- **改进权限配置**：管理员列表支持英文逗号分隔或 JSON 数组，未配置时不授予运维权限。
- **改进资源监控**：未匹配到服务器 Java 进程时，不再将内存最大的其他 Java 进程作为监控结果。
- **完善定时播报**：未配置有效群 OpenID 时跳过自动播报，机器人退出时清理后台任务。
- **增加命令输入检查**：拒绝包含换行和空字符的控制台命令。

## 部署与开发

- 新增 `bot.py` 启动入口，使用 `python bot.py` 启动，无需额外安装 `nb-cli`。
- 补充本地开发、云端更新、代理使用和配置迁移说明。
- 新增 13 项回归测试，覆盖配置读取、停服权限、接口错误和定时任务清理。

## 云服务器更新步骤

1. 在仓库外备份 `.env.prod`，记录当前提交版本，并停止机器人进程。
2. 在项目目录执行 `git pull --ff-only`。
3. 使用云端虚拟环境执行 `python -m pip install -r requirements.txt`。
4. 对照 `.env.example` 检查配置，保留自己的密钥和 OpenID。旧副本中的 `MCSM_API_BASE` / `MCSM_API_KEY` 需迁移为 `MCS_URL` / `MCS_API_KEY`。
5. 通过原有进程管理器运行 `python bot.py`，验证 `/whoami`、`/online` 和 `/reportnow`。

如果拉取时提示本地修改冲突，请先保留并合并修改，不要强制覆盖。不要用示例配置覆盖生产密钥文件。

## 验证与已知限制

- 本地 13 项回归测试、依赖检查和启动初始化验证通过，尚未进行云端真实 QQ / Minecraft 联调。
- 完整进程与目录监控仍要求机器人和 Minecraft 实例同机，并具有读取权限。
- TPS 查询当前使用 `forge tps`；其他服务端核心需要适配。
- 定时主动消息能否发送取决于 QQ 平台权限与限制。
