## 版本说明

v0.3.0 重点处理云端日志中的主动消息权限拒绝和重连事件解析异常，并将运维插件按职责拆分，方便后续维护。保留原有 20 个指令，新增 2 个播报诊断指令。

## 故障修复

- **主动播报权限拒绝**：收到 QQ 错误码 `40034105` 后，暂停对应 Bot 的主动播报重试，避免反复生成报告和发送被拒绝的请求。
- **区分离线与发送失败**：主动消息无权限不再被误报为“暂无可用 Bot”，诊断中保留最近结果和错误码。
- **重连事件兼容**：将 `nonebot-adapter-qq` 最低版本提高至 `1.7.2`，兼容 `RESUMED` 事件的空字符串数据，避免原来的 `TypeError`。
- **默认关闭主动播报**：新配置默认 `ENABLE_HOURLY_REPORT=false`；已有 `.env.prod` 中显式设置的值仍会生效。

**注意：代码不能开通 QQ 平台主动消息权限。** 无此权限时，请使用 `@机器人 /reportnow` 获取被动回复；需要自动推送时，应先在 QQ 平台核实应用和目标群的权限。

## 新增指令

| 指令 | 用途 |
| --- | --- |
| `/reportstatus` | 查看播报开关、群配置、任务状态及最近结果 |
| `/reportretry` | 平台权限修复后清除暂停状态，恢复下一轮尝试 |

两条指令均要求管理员权限。`/reportretry` 不会开通平台权限，也不会立即发送主动消息。`/reportnow` 不受主动播报暂停影响。

## 模块整理

- `__init__.py` 仅保留插件信息和模块加载入口。
- 拆出配置、权限、HTTP 请求、MCSManager 服务、监控、日志解析、报告生成和定时播报模块。
- 指令按服务器控制、状态查询、玩家管理、帮助和诊断分类。
- 合并重复的启停和玩家管理处理逻辑，移除无关的内置 `echo` 插件配置。
- 新增诊断功能无需安装额外的第三方插件。

## 云端升级

1. 备份实际使用的 `.env.prod`，停止旧机器人进程。
2. 更新完整仓库：`git pull --ff-only`。**不能只替换 `__init__.py`**，本次新增了多个模块。
3. 在云端机器人虚拟环境执行 `python -m pip install -r requirements.txt`，确保 QQ 适配器不低于 `1.7.2`。
4. 无主动消息权限时，在 `.env.prod` 中设置 `ENABLE_HOURLY_REPORT=false`。
5. 使用该虚拟环境运行 `python bot.py`，验证 `/whoami`、`/online`、`/reportnow` 和 `/reportstatus`。

从旧 `D:\Bot\BotTest1` 副本迁移时，建议使用独立的新仓库目录，按示例迁移配置，并停止旧 `QQ_OfficialBot_Test1` 插件和旧进程，避免同名指令或定时任务重复运行。不要覆盖 Minecraft 存档或生产密钥。

详细步骤：[中文云端故障处理与迁移](https://github.com/xiaomeng2568/MinecraftServerBot-QQOfficial/blob/v0.3.0/docs/troubleshooting.md)。
